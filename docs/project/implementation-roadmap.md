# WarSpark 实施路线图

## 1. 文档目的

本文档将 WarSpark MVP 和后续版本拆成可执行阶段，明确每个阶段的目标、交付物、验收标准、主要风险和不做事项。

路线图基于：

- `docs/product/warspark-prd.md`
- `docs/product/mvp-scope.md`
- `docs/product/user-flows.md`
- `docs/product/page-spec.md`
- `docs/product/content-data-policy.md`
- `docs/architecture/data-model.md`

## 2. 总体策略

WarSpark 不从完整战争工具或完整阵型图库开始，而是先完成一个可验证闭环：

1. 有基础阵型和视频样本。
2. 用户可以上传截图。
3. 系统可以返回相似阵型、相关视频、防守回放和 OpenLayout。
4. 找阵结果可以沉淀为轻量阵型库。
5. 后续再接入战争数据和复盘。

阶段顺序：

- Phase 0：产品文档和数据模型。
- Phase 1：轻量阵型库和人工样本数据。
- Phase 2：截图上传和找阵结果页。
- Phase 3：相关视频和防守回放关联。
- Phase 4：战争数据基础接入。
- Phase 5：复盘和资料沉淀。

## 3. Phase 0：产品文档和数据模型

目标：

- 在开发前锁定 MVP 边界、流程、页面、数据来源和核心数据模型。

交付物：

- MVP 范围文档。
- 用户流程文档。
- 页面规格文档。
- 内容与数据边界文档。
- 数据模型文档。
- 实施路线图。

验收标准：

- 所有 P0 文档状态为已完成。
- `documentation-status.md` 与实际文件一致。
- 文档中不存在未决占位词。
- MVP 边界明确排除登录、收藏、付费、多端 App、完整视频帧索引、自动配兵识别、AI 打法推荐。

主要风险：

- 继续扩大 MVP 范围。
- 页面规格和数据模型不一致。

风险控制：

- 新需求先对照 `mvp-scope.md`。
- 页面新增字段先对照 `data-model.md`。

不做事项：

- 不开始写业务代码。
- 不设计完整后台。
- 不写 P1 文档。

## 4. Phase 1：轻量阵型库和人工样本数据

目标：

- 先建立可浏览的阵型资产基础，支撑后续找阵结果页。

交付物：

- 阵型库列表页。
- 阵型详情页。
- 基础阵型数据模型落地。
- 阵型图片、OpenLayout、来源、审核状态、质量状态字段落地。
- 少量人工维护样本数据。

核心能力：

- 按 TH、类型、风格、来源、审核状态筛选阵型。
- 查看阵型图片。
- 打开或复制 OpenLayout。
- 展示链接状态：可用、失效、未验证、暂无。
- 展示质量状态：高可信、可参考、低可信、未知。

验收标准：

- 阵型库列表可以展示样本阵型。
- 阵型详情可以展示图片、TH、类型、来源、状态和 OpenLayout。
- 失效链接不能被复制或打开。
- 待审核或低可信阵型有明确标记。

主要风险：

- 样本数据来源不清。
- OpenLayout 和图片不匹配。
- 阵型库被做成完整内容运营系统。

风险控制：

- 所有样本数据必须记录来源。
- 低可信和待审核状态前端可见。
- MVP 只做轻量列表和详情，不做投稿、收藏、评论、付费。

不做事项：

- 不做完整阵型图库后台。
- 不做用户投稿审核。
- 不做 SEO 内容运营。

## 5. Phase 2：截图上传和找阵结果页

目标：

- 用户可以上传截图，并看到一次完整的找阵结果。

交付物：

- 找阵页。
- 上传任务创建和状态展示。
- 找阵结果页。
- 找阵任务和结果数据模型落地。
- 低置信度、无结果、失败状态。

核心能力：

- 上传阵型截图。
- 创建找阵任务。
- 展示处理状态。
- 展示识别 TH、截图质量和候选数量。
- 展示相似阵型候选。
- 从相似阵型进入阵型详情。
- 支持重新上传。

验收标准：

- 用户能从首页进入找阵页。
- 用户能完成上传到结果页的完整流程。
- 成功结果展示相似阵型。
- 低置信度结果明确提示。
- 无结果时展示重新上传、同 TH 热门视频或反馈入口。
- 失败时展示失败原因和重新上传入口。

主要风险：

- 找阵算法不成熟导致体验不可用。
- 低置信度结果误导用户。
- 上传流程依赖战争数据。

风险控制：

- MVP 可以使用人工样本和候选匹配，不承诺精确 AI。
- 低可信结果必须标记。
- 找阵流程必须能独立运行。

不做事项：

- 不做复杂图片编辑器。
- 不做批量上传。
- 不做大规模视频帧索引。
- 不做自动识别配兵或打法。

## 6. Phase 3：相关视频和防守回放关联

目标：

- 找阵结果页可以提供可学习的视频参考和防守回放。

交付物：

- 视频基础数据模型落地。
- 阵型和视频关联模型落地。
- 进攻视频分组。
- 防守回放分组。
- YouTube 时间戳跳转。
- 视频关联类型：精确关联、相似参考、同 TH 参考。

核心能力：

- 展示视频标题、频道、星数、摧毁率、时间戳、标签。
- 区分进攻视频和防守回放。
- 打开 YouTube 对应时间戳。
- 在阵型详情页展示关联视频。
- 无视频时展示空状态。

验收标准：

- 找阵结果页可以展示进攻视频和防守回放两个分组。
- 视频卡片可以打开正确时间戳。
- 相似参考和同 TH 参考不能展示为精确关联。
- 没有关联视频时，页面仍可展示相似阵型和 OpenLayout。

主要风险：

- 视频关联质量不稳定。
- 用户误以为视频是系统推荐打法。
- YouTube 链接失效。

风险控制：

- 使用“相关视频”“视频参考”文案。
- 记录关联类型和审核状态。
- 失效视频展示不可访问状态。

不做事项：

- 不下载 YouTube 视频。
- 不自动解析视频画面。
- 不自动提取配兵链接。
- 不做 AI 总结打法。

## 7. Phase 4：战争数据基础接入

目标：

- 从战争上下文进入找阵流程，让 WarSpark 从单点找阵工具升级为战前情报入口。

交付物：

- 部落 tag / 玩家 tag 输入。
- 战争情报页基础版。
- 战争快照数据模型落地。
- 战争成员数据模型落地。
- 目标情报入口。
- 找阵任务绑定战争目标上下文。

核心能力：

- 查询部落或玩家基础信息。
- 展示当前战争概览。
- 展示 TH 分布。
- 展示敌我成员列表。
- 从敌方目标进入找阵流程。
- 找阵结果页展示目标上下文。

验收标准：

- 用户可以从战争情报页选择敌方目标进入找阵。
- 找阵结果页可以展示敌方序号、玩家名、TH 和当前被打情况。
- 官方 API 不可用时，找阵流程仍可独立使用。
- 无法访问战争数据时有明确错误状态。

主要风险：

- 官方 API 缓存和权限导致数据不完整。
- 战争数据范围扩张为完整 War Report。
- 找阵流程被战争数据耦合。

风险控制：

- 战争数据只服务目标上下文。
- MVP 找阵流程保持独立。
- 历史战争和完整 CWL 分析不进入本阶段。

不做事项：

- 不做完整 War Report。
- 不做多账号同步。
- 不做推送提醒。
- 不做历史战争分析。

## 8. Phase 5：复盘和资料沉淀

目标：

- 战后数据反哺阵型库、视频资料库和后续找阵排序。

交付物：

- 复盘页基础版。
- 攻击记录展示。
- 防守记录展示。
- 阵型表现统计。
- 攻击结果表现统计。
- 关键阵型和关键视频标记。

核心能力：

- 查看战争结果。
- 查看攻击记录和防守记录。
- 关联阵型详情。
- 关联视频时间戳。
- 将复盘结果写回阵型和视频资料库。

验收标准：

- 用户能查看一场战争的基础复盘信息。
- 用户能从复盘记录进入阵型详情。
- 关键阵型和视频能被标记并沉淀。
- 后续找阵结果可以引用历史表现。

主要风险：

- 复盘功能膨胀成完整分析平台。
- 攻击原因、失败原因难以自动判断。
- 历史数据来源不稳定。

风险控制：

- 先做记录展示和人工标记。
- 不做自动失败原因分析。
- 不做复杂评分模型。

不做事项：

- 不做完整统计分析系统。
- 不做 AI 复盘总结。
- 不做复杂图表大屏。

## 9. 跨阶段验收要求

每个阶段完成前必须检查：

- 是否符合 `mvp-scope.md`。
- 是否符合 `content-data-policy.md`。
- 是否有页面状态：加载、空、错误、低置信度、链接失效。
- 是否有对应数据模型或预留字段。
- 是否没有引入明确不做事项。

每个阶段完成后必须更新：

- `docs/project/documentation-status.md`
- 阶段验收记录。
- 后续阶段风险。

## 10. 推荐开发顺序

建议实际开发顺序：

1. 数据迁移和基础实体。
2. 人工样本数据。
3. 阵型库列表和详情。
4. 找阵上传任务。
5. 找阵结果页。
6. 视频和防守回放关联。
7. 战争数据接入。
8. 复盘沉淀。

原因：

- 阵型库先行可以提供找阵结果页需要的基础资产。
- 找阵上传先用样本结果跑通流程。
- 视频关联在找阵结果页稳定后接入。
- 战争数据最后接入，避免过早耦合。

## 12. 验收标准

实施路线图文档视为完成时，需要满足：

- 覆盖 Phase 0 到 Phase 5。
- 每个阶段包含目标、交付物、核心能力、验收标准、主要风险和不做事项。
- 明确先做产品文档，再做阵型库，再做找阵，再做视频，再做战争数据，再做复盘。
- 不引入超出 MVP 的登录、付费、完整 War Report、大规模视频帧索引、AI 打法推荐等能力。
