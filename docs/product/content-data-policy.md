# WarSpark 内容与数据边界说明

## 1. 文档目的

本文档定义 WarSpark 在 MVP 和后续阶段中可以使用哪些内容和数据、不能使用哪些内容和数据，以及阵型图片、OpenLayout、YouTube 时间戳、官方 CoC API、授权导入等来源的处理规则。

WarSpark 涉及用户上传图片、公开阵型链接、第三方视频、官方游戏数据和可能的社区资料导入。为了降低产品、技术和合规风险，所有内容资产都需要记录来源、置信度、审核状态和可用状态。

## 2. 核心原则

1. 只使用公开、用户提供或授权导入的数据。
2. 不绕过登录、权限、付费、私域社区或平台限制。
3. 不下载 YouTube 视频，不做未授权批量抓取。
4. 不做游戏客户端自动化、逆向或模拟操作。
5. 找阵结果和阵型库资产必须保留来源和质量状态。
6. 低置信度内容必须对用户明确标识。
7. 外部链接失效时必须禁用可执行动作。

## 3. 可用数据来源

### 3.1 用户上传

适用内容：

- 阵型截图。
- 战争目标截图。
- 用户手动补充的阵型图片。
- 用户手动补充的视频链接或备注。

允许用途：

- 截图找阵。
- 生成找阵任务。
- 作为阵型记录的候选图片。
- 作为人工审核素材。

必须记录：

- 上传时间。
- 文件类型。
- 图片尺寸。
- 上传来源页面。
- 关联找阵任务。
- 处理状态。

限制：

- 不默认公开展示用户上传原图。
- 如果用户上传图被沉淀为阵型库资产，需要经过质量状态标记。
- 包含明显无关内容或不可识别内容时，不进入阵型库。

### 3.2 公开阵型页面

适用内容：

- 公开网页中的阵型图片。
- 公开网页中的 OpenLayout 或官方复制链接。
- 公开网页中的 TH、类型、风格、标题、发布时间等基础信息。

允许用途：

- 作为候选阵型来源。
- 作为人工审核和整理来源。
- 进入轻量阵型库。

必须记录：

- 来源 URL。
- 采集时间。
- 阵型图片 URL 或本地资产引用。
- OpenLayout URL。
- 来源站点名称。
- 来源类型：公开页面。
- 审核状态。

限制：

- 不复制第三方品牌文案作为 WarSpark 文案。
- 不绕过反爬、登录、付费或访问限制。
- 不把低可信来源直接标记为已审核。
- 图片和链接必须能对应到同一个阵型上下文，否则标记为候选或待审核。

### 3.3 OpenLayout

适用内容：

- `link.clashofclans.com` 或其他可打开阵型的公开链接。
- 第三方页面公开提供的 OpenLayout。
- 用户提交的 OpenLayout。

允许用途：

- 在找阵结果页展示。
- 在阵型详情页打开或复制。
- 作为阵型库资产的一部分。

必须记录：

- 链接 URL。
- 链接类型。
- 来源。
- 链接状态：可用、失效、待验证。
- 最后验证时间。

限制：

- 不保证每个阵型都有 OpenLayout。
- 不自动修复失效链接。
- 链接失效时不得继续展示为可复制状态。

### 3.4 YouTube 视频和时间戳

适用内容：

- 公开视频 URL。
- YouTube 视频 ID。
- 视频标题。
- 频道名称。
- 用户可打开的时间戳。
- 手动维护的星数、摧毁率、TH、视频标签。

允许用途：

- 找阵结果页展示相关攻击视频。
- 找阵结果页展示防守回放。
- 阵型详情页展示关联视频。
- 作为用户学习参考。

必须记录：

- YouTube 视频 ID。
- 时间戳秒数。
- 视频标题。
- 频道名称。
- 关联阵型。
- 关联类型：精确关联、相似参考、同 TH 参考。
- 记录来源。

限制：

- 不下载 YouTube 视频。
- 不自动抓取视频画面。
- 不承诺自动识别流派或配兵。
- 不把视频标题中的说法直接当作 WarSpark 的事实结论。
- 不使用登录绕过或付费内容。

### 3.5 Clash of Clans 官方 API

适用内容：

- 部落信息。
- 玩家信息。
- 当前战争信息。
- CWL 信息。
- 成员列表。
- 攻击次数、星数、摧毁率等结构化数据。

允许用途：

- V1 战争情报页。
- 目标上下文。
- 战争数据快照。
- 复盘基础数据。

必须记录：

- 查询 tag。
- 查询时间。
- API 响应缓存时间。
- 数据来源：官方 API。
- 失败原因。

限制：

- 尊重官方 API 限制和缓存。
- 不把官方 API 无法提供的历史数据伪装成官方数据。
- 无法访问战争数据时，找阵流程仍可独立运行。

### 3.6 授权导入

适用内容：

- 用户提供的 CSV。
- 用户提供的 JSON。
- 用户提供的 HTML 导出。
- 用户拥有权限的 Discord 导出。
- 用户控制的 bot 在授权服务器或频道内获得的数据。

允许用途：

- 批量导入阵型链接。
- 批量导入阵型图片。
- 批量导入视频时间戳。
- 进入人工审核队列。

必须记录：

- 导入文件名。
- 导入时间。
- 提供者。
- 授权说明。
- 解析结果。
- 失败记录。

限制：

- 不使用 self-bot。
- 不抓取私有 Discord 或 Telegram。
- 不绕过频道权限。
- 没有授权说明的数据不进入自动入库流程。

### 3.7 人工维护

适用内容：

- 人工整理的阵型图片。
- 人工整理的 OpenLayout。
- 人工整理的视频时间戳。
- 人工标注的 TH、类型、风格、来源、质量状态。

允许用途：

- MVP 样本数据。
- 视频关联。
- 阵型库初始内容。
- 质量审核。

必须记录：

- 维护人或维护来源。
- 维护时间。
- 修改字段。
- 审核状态。

限制：

- 人工标注不是算法事实，需要保留审核状态。
- 不用人工维护绕过来源记录。

## 4. 禁用数据来源和行为

以下行为不允许进入 MVP，也不作为默认后续路径：

- 私有 Discord / Telegram 抓取。
- self-bot 或账号登录抓取。
- 绕过登录权限、付费墙或访问限制。
- YouTube 视频下载。
- 未授权批量抓取 YouTube 视频画面。
- 游戏客户端自动化、逆向或模拟操作。
- 复制第三方站点品牌、文案或付费内容。
- 将来源不明的数据标记为已审核。
- 将低置信度匹配展示成精确匹配。

## 5. 内容状态模型

### 5.1 来源类型

| 来源类型 | 含义 |
| --- | --- |
| `user_upload` | 用户上传。 |
| `public_page` | 公开网页。 |
| `official_api` | Clash of Clans 官方 API。 |
| `authorized_import` | 用户授权导入。 |
| `manual_entry` | 人工录入。 |
| `search_result` | 找阵结果沉淀。 |

### 5.2 审核状态

| 状态 | 含义 |
| --- | --- |
| `reviewed` | 已人工审核。 |
| `pending_review` | 等待审核。 |
| `rejected` | 不进入公开展示。 |
| `needs_update` | 需要补充或修复。 |

### 5.3 质量状态

| 状态 | 含义 |
| --- | --- |
| `high_confidence` | 高可信。 |
| `medium_confidence` | 可参考。 |
| `low_confidence` | 低可信，需要明确提示。 |
| `unknown` | 暂未判断。 |

### 5.4 链接状态

| 状态 | 含义 |
| --- | --- |
| `active` | 可用。 |
| `broken` | 失效。 |
| `unverified` | 未验证。 |
| `missing` | 暂无链接。 |

## 6. 阵型图片处理规则

必须记录：

- 图片来源。
- 原始 URL 或上传记录。
- 图片尺寸。
- 关联阵型。
- 质量状态。
- 审核状态。

允许：

- 展示已审核阵型图片。
- 展示待审核图片并标记状态。
- 使用图片生成找阵候选结果。

不允许：

- 来源不明图片直接进入公开阵型库。
- 图片和 OpenLayout 未确认对应关系时标记为已审核。
- 低质量截图伪装成标准阵型图。

## 7. OpenLayout 处理规则

必须记录：

- OpenLayout URL。
- 来源类型。
- 来源页面或导入文件。
- 链接状态。
- 最后验证时间。

展示规则：

- `active`：允许复制和打开。
- `broken`：展示失效，不允许复制和打开。
- `unverified`：允许展示待验证标记。
- `missing`：展示暂无复制链接。

## 8. 视频时间戳处理规则

必须记录：

- YouTube 视频 ID。
- 时间戳秒数。
- 频道名称。
- 视频标题。
- 关联阵型或相似阵型。
- 关联类型。
- 审核状态。

展示规则：

- 精确关联：视频和阵型有较高可信关联。
- 相似参考：视频与相似阵型相关。
- 同 TH 参考：只作为同 TH 视频参考。

不允许：

- 未确认关联的视频展示为精确关联。
- 把视频标题中的流派当作系统推荐。
- 在 MVP 中承诺配兵或完整打法。

## 9. 官方 API 数据处理规则

使用规则：

- 只通过官方 API 获取部落、玩家、战争和 CWL 数据。
- 缓存响应，避免频繁请求。
- API 不可用时展示明确错误状态。
- 官方 API 无法提供的数据不伪装为官方数据。

战争数据与找阵关系：

- 找阵流程不依赖战争数据。
- 战争数据用于提供目标上下文。
- 战争目标可绑定找阵任务。
- 找阵结果页需要能在无战争上下文时独立展示。

## 10. 授权导入处理规则

导入前需要明确：

- 数据来自哪里。
- 用户是否有权限提供。
- 数据格式是什么。
- 是否允许用于阵型库或仅用于个人整理。

导入后需要记录：

- 成功条数。
- 失败条数。
- 待审核条数。
- 失效链接条数。
- 缺少图片条数。

不允许：

- 用授权导入名义处理来源不明的私域抓取。
- 将导入数据自动全部标记为已审核。

## 11. MVP 内容策略

MVP 推荐内容来源组合：

1. 人工维护少量高质量阵型图片。
2. 人工维护少量 OpenLayout。
3. 人工维护少量相关 YouTube 时间戳。
4. 使用用户上传截图生成找阵任务。
5. 使用找阵结果沉淀轻量阵型库。

MVP 不依赖：

- 大规模自动采集。
- 完整视频帧索引。
- 完整战争历史数据。
- 用户投稿系统。

## 12. 验收标准

内容与数据边界文档视为完成时，需要满足：

- 明确列出可用数据来源。
- 明确列出禁用数据来源和行为。
- 明确 OpenLayout、阵型图片、YouTube 时间戳、官方 API、授权导入的处理规则。
- 明确来源类型、审核状态、质量状态、链接状态。
- 明确 MVP 内容策略。
- 能支撑后续数据模型中的来源、状态和审核字段设计。
