# WarSpark 内容与数据边界说明

## 1. 文档目的

本文档定义 WarSpark 在 MVP 和后续阶段中可以使用哪些内容和数据、不能使用哪些内容和数据，以及阵型图片、阵型链接、YouTube 时间戳、Clash of Clans 官方 API、授权导入等来源的处理规则。

WarSpark 涉及匿名用户上传图片、公开阵型资料、第三方视频、官方游戏数据和可能的社区资料导入。为了降低产品、技术和合规风险，所有内容资产都需要记录来源、置信度、审核状态和可用状态。

## 2. 核心原则

1. 只使用公开、用户提供或授权导入的数据。
2. 不绕过登录、权限、付费、私域社区或平台限制。
3. 不下载 YouTube 视频，不做未授权批量抓取。
4. 不做游戏客户端自动化、逆向或模拟操作。
5. 找阵结果和阵型库资产必须保留来源和质量状态。
6. 低置信度内容必须对用户明确标识。
7. 外部链接失效时必须禁用可执行动作。
8. 能自动处理的环节优先自动处理，后台只处理低置信度、冲突、失效和异常样本。

## 3. 可用数据来源

### 3.1 匿名用户上传

适用内容：

- 阵型截图。
- 战争目标截图。

允许用途：

- 截图找阵。
- 创建找阵任务。
- 自动识别 TH 和截图质量。
- 作为候选阵型图片进入后台复核队列。

必须记录：

- 上传时间。
- 文件类型。
- 图片尺寸。
- 文件大小。
- 上传来源页面。
- 关联找阵任务。
- 处理状态。
- 匿名上传 IP 哈希或限流标识。

上传限制：

- 仅允许 `jpg`、`jpeg`、`png`、`webp`。
- 单张图片最大 10MB。
- 图片最短边不低于 512px。
- 服务端归一化图片，最长边不超过 4096px。
- 服务端移除 EXIF 和其他隐私元数据。
- 匿名上传按 IP 或等效匿名标识限流：建议 5 次/分钟、50 次/小时。
- 原始上传图默认保留 7 天；沉淀为阵型库资产时另存标准化图片。

限制：

- 不默认公开展示匿名用户上传原图。
- 包含明显无关内容、不可识别内容或疑似隐私内容时，不进入阵型库。
- 上传图片不能包含视频、压缩包、文档或其他非图片文件。

### 3.2 公开阵型页面

适用内容：

- 公开网页中的阵型图片。
- 公开网页中的官方游戏打开链接或来源页面链接。
- 公开网页中的 TH、类型、风格、标题、发布时间等基础信息。

允许用途：

- 作为候选阵型来源。
- 进入自动解析和链接检查流程。
- 进入轻量阵型库或后台复核队列。

必须记录：

- 来源 URL。
- 采集时间。
- 阵型图片 URL 或本地资产引用。
- 链接 URL。
- 链接类型。
- 来源站点名称。
- 来源类型：公开页面。
- 审核状态。

限制：

- 不复制第三方品牌文案作为 WarSpark 文案。
- 不绕过反爬、登录、付费或访问限制。
- 不把低可信来源直接标记为已审核。
- 图片和链接必须能对应到同一个阵型上下文，否则标记为候选或待复核。

### 3.3 阵型链接

WarSpark 用户侧统一称为“阵型链接”“打开阵型”或“复制阵型链接”。技术字段按以下类型保存：

| 链接类型 | 含义 |
| --- | --- |
| `official_open_layout` | `link.clashofclans.com` 等官方游戏打开链接。 |
| `source_page` | 第三方公开阵型页面链接。 |
| `backup` | 备用阵型链接或镜像来源。 |

允许用途：

- 在找阵结果页展示。
- 在阵型详情页打开或复制。
- 作为阵型库资产的一部分。

必须记录：

- 链接 URL。
- 链接类型。
- 来源。
- 链接状态：可用、失效、待验证、暂无。
- 最后验证时间。

限制：

- 不保证每个阵型都有官方游戏打开链接。
- 不自动修复失效链接。
- 链接失效时不得继续展示为可复制状态。

### 3.4 YouTube 视频和时间戳

适用内容：

- 公开视频 URL。
- YouTube 视频 ID。
- 视频标题。
- 频道名称。
- 用户可打开的时间戳。
- 手动或后台维护的星数、摧毁率、TH、视频标签。

允许用途：

- 找阵结果页展示相关攻击视频。
- 找阵结果页展示防守回放。
- 阵型详情页展示关联视频。
- 作为用户学习参考。

必须记录：

- YouTube 视频 ID。
- 时间戳秒数。
- 视频标题。
- 频道名称。
- 关联阵型。
- 关联类型：精确关联、相似参考、同 TH 参考。
- 记录来源。

限制：

- 不下载 YouTube 视频。
- 不自动抓取视频画面。
- 不承诺自动识别流派或配兵。
- 不把视频标题中的说法直接当作 WarSpark 的事实结论。
- 不使用登录绕过或付费内容。

### 3.5 Clash of Clans 官方 API

适用内容：

- 部落信息。
- 玩家信息。
- 当前战争信息。
- CWL 基础信息。
- 成员列表。
- TH 分布。
- 攻击次数、星数、摧毁率等结构化数据。

允许用途：

- MVP 战争情报页。
- 战争目标上下文。
- 战争数据快照。
- 复盘基础数据。
- 找阵任务绑定敌方目标。

必须记录：

- 查询 tag。
- 查询时间。
- API 响应缓存时间。
- 数据来源：官方 API。
- 失败原因。

限制：

- 尊重官方 API 限制和缓存。
- 不把官方 API 无法提供的历史数据伪装成官方数据。
- 无法访问战争数据时，找阵流程仍可独立运行。

### 3.6 授权导入

适用内容：

- 用户提供的 CSV。
- 用户提供的 JSON。
- 用户提供的 HTML 导出。
- 用户拥有权限的 Discord 导出。
- 用户控制的 bot 在授权服务器或频道内获得的数据。

允许用途：

- 批量导入阵型链接。
- 批量导入阵型图片。
- 批量导入视频时间戳。
- 进入自动解析流程。
- 进入后台复核队列。

必须记录：

- 导入文件名。
- 导入时间。
- 提供者。
- 授权说明。
- 解析结果。
- 失败记录。

限制：

- 不使用 self-bot。
- 不抓取私有 Discord 或 Telegram。
- 不绕过频道权限。
- 没有授权说明的数据不进入自动入库流程。

### 3.7 内部后台维护

适用内容：

- 后台补充的阵型图片。
- 后台补充的阵型链接。
- 后台补充的视频时间戳。
- 后台标注的 TH、类型、风格、来源、质量状态。

允许用途：

- 修复自动处理失败的数据。
- 处理低置信度和冲突样本。
- 补充视频关联。
- 修复失效链接。

必须记录：

- 操作人。
- 操作时间。
- 修改字段。
- 审核状态。
- 操作日志。

限制：

- 后台标注不是算法事实，需要保留审核状态。
- 不用后台维护绕过来源记录。
- 后台只作为兜底能力，不替代自动处理主流程。

## 4. 禁用数据来源和行为

以下行为不允许进入 MVP，也不作为默认后续路径：

- 私有 Discord / Telegram 抓取。
- self-bot 或账号登录抓取。
- 绕过登录权限、付费墙或访问限制。
- YouTube 视频下载。
- 未授权批量抓取 YouTube 视频画面。
- 游戏客户端自动化、逆向或模拟操作。
- 复制第三方站点品牌、文案或付费内容。
- 将来源不明的数据标记为已审核。
- 将低置信度匹配展示成精确匹配。

## 5. 内容状态模型

### 5.1 来源类型

| 来源类型 | 含义 |
| --- | --- |
| `user_upload` | 用户匿名上传。 |
| `public_page` | 公开网页。 |
| `official_api` | Clash of Clans 官方 API。 |
| `authorized_import` | 用户授权导入。 |
| `automated_pipeline` | 自动识别、匹配、解析或链接检查流程生成。 |
| `manual_entry` | 内部后台录入或修复。 |
| `search_result` | 找阵结果沉淀。 |

### 5.2 审核状态

| 状态 | 含义 |
| --- | --- |
| `reviewed` | 已自动高可信确认或后台审核。 |
| `pending_review` | 等待后台复核。 |
| `rejected` | 不进入公开展示。 |
| `needs_update` | 需要补充或修复。 |

### 5.3 质量状态

| 状态 | 含义 |
| --- | --- |
| `high_confidence` | 高可信。 |
| `medium_confidence` | 可参考。 |
| `low_confidence` | 低可信，需要明确提示。 |
| `unknown` | 暂未判断。 |

### 5.4 链接状态

| 状态 | 含义 |
| --- | --- |
| `active` | 可用。 |
| `broken` | 失效。 |
| `unverified` | 未验证。 |
| `missing` | 暂无链接。 |

## 6. 阵型图片处理规则

必须记录：

- 图片来源。
- 原始 URL 或上传记录。
- 标准化图片资产 ID。
- 图片尺寸。
- 关联阵型。
- 质量状态。
- 审核状态。

允许：

- 展示已审核或自动高可信阵型图片。
- 展示待复核图片并标记状态。
- 使用图片生成找阵候选结果。

不允许：

- 来源不明图片直接进入公开阵型库。
- 图片和阵型链接未确认对应关系时标记为已审核。
- 低质量截图伪装成标准阵型图。

## 7. 阵型链接处理规则

必须记录：

- 链接 URL。
- 链接类型。
- 来源类型。
- 来源页面或导入文件。
- 链接状态。
- 最后验证时间。

展示规则：

- `active`：允许复制和打开。
- `broken`：展示失效，不允许复制和打开。
- `unverified`：允许展示待验证标记。
- `missing`：展示暂无复制链接。

## 8. 视频时间戳处理规则

必须记录：

- YouTube 视频 ID。
- 时间戳秒数。
- 频道名称。
- 视频标题。
- 关联阵型或相似阵型。
- 关联类型。
- 审核状态。

展示规则：

- 精确关联：视频和阵型有较高可信关联。
- 相似参考：视频与相似阵型相关。
- 同 TH 参考：只作为同 TH 视频参考。

不允许：

- 未确认关联的视频展示为精确关联。
- 把视频标题中的流派当作系统推荐。
- 在 MVP 中承诺配兵或完整打法。

## 9. 官方 API 数据处理规则

使用规则：

- MVP 直接接入官方 API 获取部落、玩家、当前战争和 CWL 基础数据。
- 缓存响应，避免频繁请求。
- API 不可用时展示明确错误状态。
- 官方 API 无法提供的数据不伪装为官方数据。

战争数据与找阵关系：

- 找阵流程不依赖战争数据。
- 战争数据用于提供目标上下文。
- 战争目标可绑定找阵任务。
- 找阵结果页需要能在无战争上下文时独立展示。

## 10. 授权导入处理规则

导入前需要明确：

- 数据来自哪里。
- 用户是否有权限提供。
- 数据格式是什么。
- 是否允许用于阵型库或仅用于个人整理。

导入后需要记录：

- 成功条数。
- 失败条数。
- 自动入库条数。
- 待复核条数。
- 失效链接条数。
- 缺少图片条数。

不允许：

- 用授权导入名义处理来源不明的私域抓取。
- 将导入数据自动全部标记为已审核。

## 11. MVP 内容策略

MVP 推荐内容来源组合：

1. 自动处理用户上传截图并生成找阵任务。
2. 自动沉淀高置信度找阵结果到轻量阵型库。
3. 自动检查阵型链接可用状态。
4. 后台维护少量高质量初始阵型图片、阵型链接和 YouTube 时间戳。
5. 后台复核低置信度、冲突、失效和异常数据。
6. 使用官方 API 提供战争情报和目标上下文。

MVP 不依赖：

- 大规模自动采集。
- 完整视频帧索引。
- 完整战争历史归档。
- 用户投稿系统。
- 公开社区审核系统。

## 12. 验收标准

内容与数据边界文档视为完成时，需要满足：

- 明确列出可用数据来源。
- 明确列出禁用数据来源和行为。
- 明确阵型链接、阵型图片、YouTube 时间戳、官方 API、授权导入的处理规则。
- 明确来源类型、审核状态、质量状态、链接状态。
- 明确匿名上传文件限制、隐私处理、限流和保留周期。
- 明确 MVP 内容策略。
- 能支撑后续数据模型中的来源、状态和审核字段设计。
