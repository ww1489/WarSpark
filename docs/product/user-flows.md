# WarSpark 用户流程说明

## 1. 文档目的

本文档定义 WarSpark MVP 和后续 V1/V2 需要支持的核心用户流程。页面规格、API 契约、数据模型和验收清单应引用本文档中的流程编号，避免各文档对用户路径理解不一致。

当前流程以 MVP 为主，覆盖：

- 从首页上传截图找阵。
- 从战争目标进入找阵。
- 找阵结果进入阵型详情。
- 找阵结果沉淀为阵型库资产。
- 战后复盘沉淀资料。
- 低置信度、无结果、链接失效等异常流程。

## 2. 流程角色

| 角色 | 关注点 |
| --- | --- |
| 普通参战玩家 | 快速上传目标截图，找到相关视频和可复制阵型。 |
| 部落战指挥 | 从战争目标进入找阵，判断目标风险和参考视频。 |
| 阵型研究者 | 浏览阵型库，沉淀阵型、视频、防守表现。 |
| 内容维护者 | 标记来源、质量状态、链接状态和视频关联。 |

## 3. 状态定义

### 3.1 找阵任务状态

| 状态 | 含义 | 用户可见行为 |
| --- | --- | --- |
| `created` | 已创建上传任务 | 显示上传完成，等待处理。 |
| `processing` | 正在识别和匹配 | 显示处理中，不展示结果。 |
| `matched` | 找到候选结果 | 展示识别信息、相似阵型、视频和链接。 |
| `low_confidence` | 有候选但可信度低 | 展示候选，同时提示需要人工判断。 |
| `no_result` | 没有找到候选 | 展示无结果页和替代入口。 |
| `failed` | 上传或处理失败 | 展示失败原因和重新上传入口。 |

### 3.2 阵型记录状态

| 状态 | 含义 | 用户可见行为 |
| --- | --- | --- |
| `reviewed` | 已审核 | 正常展示，可作为高可信结果。 |
| `pending_review` | 待审核 | 展示待审核标记。 |
| `low_confidence` | 低置信度 | 展示低置信度提示。 |
| `link_broken` | 链接失效 | 阵型可展示，但复制链接不可用。 |
| `hidden` | 暂不展示 | 不进入公开列表。 |

## 4. F1 从首页上传截图找阵

目标：用户不需要先输入部落信息，也可以直接上传截图寻找相似阵型和相关视频。

入口：

- 首页 / 作战台的“上传阵型截图”入口。
- 阵型库或找阵结果页中的“重新上传”入口。

主流程：

1. 用户进入首页 / 作战台。
2. 用户点击上传阵型截图。
3. 系统展示上传要求：建议截图清晰、包含完整阵型、尽量减少 UI 遮挡。
4. 用户选择图片并提交。
5. 系统创建找阵任务，状态为 `created`。
6. 系统进入处理页，状态变为 `processing`。
7. 系统完成 TH 识别和候选匹配。
8. 如果找到候选结果，状态变为 `matched`。
9. 用户进入找阵结果页。
10. 用户查看识别信息、相似阵型、进攻视频、防守回放和 OpenLayout。

结束状态：

- 用户打开相关视频。
- 用户复制或打开 OpenLayout。
- 用户进入阵型详情页。
- 用户重新上传另一张截图。

异常分支：

- 图片格式不支持：停留在上传页，提示支持格式。
- 图片过大：提示压缩或重新选择。
- 截图质量差：进入 `low_confidence` 或 `failed` 状态。
- 处理失败：进入失败页，允许重新上传。

## 5. F2 从战争目标进入找阵

目标：用户从当前战争上下文进入某个敌方目标的找阵流程。

入口：

- 战争情报页的敌方成员列表。
- 目标情报页的“上传该目标阵型截图”入口。

主流程：

1. 用户输入部落 tag 或玩家 tag。
2. 系统展示战争情报入口或基础占位。
3. 用户选择敌方目标。
4. 系统进入目标情报页。
5. 用户上传该目标的阵型截图。
6. 系统创建找阵任务，并绑定目标上下文。
7. 系统展示处理状态。
8. 系统返回找阵结果。
9. 找阵结果页展示目标基础信息：序号、玩家名、TH、当前被打情况。
10. 用户查看相似阵型、相关攻击视频和防守回放。

结束状态：

- 用户打开视频学习。
- 用户复制 OpenLayout。
- 用户标记该目标已查看。
- 用户返回战争目标列表。

MVP 简化：

- 战争数据可先使用手动输入或样例数据。
- 找阵流程必须能独立完成，不依赖战争数据。

异常分支：

- 部落 tag 不存在：提示 tag 无效。
- 战争数据不可访问：保留找阵入口，提示无法读取战争信息。
- 目标 TH 与截图识别 TH 不一致：提示用户确认截图是否对应当前目标。

## 6. F3 找阵结果进入阵型详情

目标：用户可以从找阵结果中的相似阵型进入完整阵型详情。

入口：

- 找阵结果页的相似阵型卡片。
- 找阵结果页的 OpenLayout 区域。
- 阵型库列表。

主流程：

1. 用户在找阵结果页看到相似阵型卡片。
2. 用户点击阵型卡片。
3. 系统进入阵型详情页。
4. 阵型详情页展示阵型图片、TH、类型、风格、来源、质量状态。
5. 页面展示 OpenLayout 状态。
6. 页面展示关联视频、防守回放和相似阵型。
7. 用户打开视频、复制链接或返回结果页。

结束状态：

- 用户完成复制或打开链接。
- 用户继续浏览相似阵型。
- 用户返回找阵结果页。

异常分支：

- 阵型状态为 `pending_review`：展示待审核标记。
- 阵型状态为 `low_confidence`：提示用户谨慎参考。
- OpenLayout 失效：展示失效状态，不提供复制动作。
- 图片不可用：展示占位图和来源状态。

## 7. F4 从找阵结果沉淀阵型库

目标：找阵命中的阵型图片和 OpenLayout 不只作为一次性结果，而是沉淀为可浏览的阵型库资产。

触发条件：

- 找阵结果中包含可用阵型图片。
- 找阵结果中包含 OpenLayout 或其他复制链接。
- 找阵结果有足够 TH、类型、来源信息。

主流程：

1. 系统生成找阵结果。
2. 系统检查是否已有相同或相似阵型记录。
3. 如果存在记录，系统关联本次找阵结果。
4. 如果不存在记录，系统创建新的阵型记录。
5. 新记录写入来源：找阵命中、公开页面、授权导入或人工录入。
6. 新记录写入质量状态：`reviewed`、`pending_review` 或 `low_confidence`。
7. 用户可以从找阵结果进入该阵型详情。
8. 该阵型可按状态进入阵型库列表。

结束状态：

- 阵型进入轻量阵型库。
- 找阵结果和阵型记录建立关联。
- 后续用户可以复用该阵型。

异常分支：

- 缺少图片：不自动创建阵型记录，只保留找阵结果。
- 缺少 OpenLayout：可创建阵型记录，但链接状态为无可用链接。
- 低置信度：进入阵型库时必须带低置信度标记。
- 重复阵型：关联到已有记录，不重复创建。

## 8. F5 阵型库浏览

目标：用户可以浏览找阵沉淀下来的阵型资产。

入口：

- 首页辅助入口。
- 找阵结果页的相似阵型。
- 阵型详情页的相似阵型。

主流程：

1. 用户进入阵型库列表页。
2. 系统展示阵型卡片列表。
3. 用户使用筛选项：TH、类型、风格、来源、审核状态。
4. 系统刷新列表。
5. 用户点击阵型卡片。
6. 系统进入阵型详情页。

结束状态：

- 用户复制或打开 OpenLayout。
- 用户打开关联视频。
- 用户继续浏览相似阵型。

异常分支：

- 无筛选结果：展示空状态和重置筛选入口。
- OpenLayout 失效：列表中标记链接不可用。
- 阵型待审核：列表和详情均展示状态。

## 9. F6 无结果流程

目标：当系统无法找到相似阵型时，也给用户明确下一步。

触发条件：

- 找阵任务状态为 `no_result`。

流程：

1. 系统展示无结果页。
2. 页面展示已识别到的基础信息，如 TH 或截图质量提示。
3. 页面说明没有找到足够可信的相似阵型。
4. 页面提供重新上传入口。
5. 页面提供同 TH 热门视频入口。
6. 页面提供手动提交入口或后续反馈入口。

结束状态：

- 用户重新上传。
- 用户查看同 TH 热门视频。
- 用户离开流程。

不允许：

- 不把无结果包装成低可信度匹配。
- 不展示伪造的精确结果。

## 10. F7 低置信度流程

目标：有候选结果但可信度不足时，明确提示用户谨慎参考。

触发条件：

- 找阵任务状态为 `low_confidence`。
- 阵型记录状态为 `low_confidence`。

流程：

1. 系统展示低置信度提示。
2. 页面展示识别到的 TH 和候选阵型。
3. 候选阵型卡片展示匹配等级。
4. 相关视频标记为相似参考或同 TH 参考。
5. 用户可以继续查看，但页面不承诺精确匹配。

结束状态：

- 用户打开视频。
- 用户进入阵型详情。
- 用户重新上传更清晰截图。

不允许：

- 不把低置信度候选放在“精确匹配”区域。
- 不隐藏低置信度原因。

## 11. F8 外部链接失效流程

目标：OpenLayout 或视频链接失效时，用户能理解当前状态。

触发条件：

- OpenLayout 链接状态为失效。
- YouTube 视频不可访问。

流程：

1. 系统在卡片或详情页展示失效状态。
2. 对失效 OpenLayout 禁用复制或打开动作。
3. 对失效视频展示不可访问状态。
4. 如果有备用链接，展示备用入口。
5. 如果没有备用链接，保留阵型或视频记录，但不展示可用操作。

结束状态：

- 用户使用备用链接。
- 用户查看其他相似阵型或视频。
- 内容维护者后续修复链接。

## 12. F9 战后复盘沉淀资料

目标：战后记录可以反哺阵型库和视频资料库。

入口：

- V2 复盘页。
- 阵型详情页的防守记录区域。

主流程：

1. 战争结束后，用户进入复盘页。
2. 系统展示攻击记录和防守记录。
3. 用户标记关键阵型。
4. 用户标记关键视频或补充备注。
5. 系统将阵型、视频、攻击结果、防守结果关联到资料库。
6. 后续找阵结果可引用这些历史表现。

MVP 处理：

- 只预留数据结构和页面入口。
- 不实现完整复盘页。

## 13. 流程优先级

| 流程 | MVP 优先级 | 说明 |
| --- | --- | --- |
| F1 从首页上传截图找阵 | P0 | MVP 主流程。 |
| F3 找阵结果进入阵型详情 | P0 | 支撑轻量阵型库。 |
| F4 从找阵结果沉淀阵型库 | P0 | 支撑内容资产复用。 |
| F5 阵型库浏览 | P0 | 支撑轻量阵型库。 |
| F6 无结果流程 | P0 | 防止失败状态不可用。 |
| F7 低置信度流程 | P0 | 防止误导用户。 |
| F8 外部链接失效流程 | P0 | 支撑链接质量状态。 |
| F2 从战争目标进入找阵 | P1 | V1 完整实现，MVP 预留结构。 |
| F9 战后复盘沉淀资料 | P2 | V2 完整实现，MVP 预留结构。 |

## 14. 验收标准

用户流程文档视为完成时，需要满足：

- 覆盖首页找阵、战争目标找阵、阵型详情、阵型库沉淀、复盘沉淀。
- 覆盖正常、低置信度、无结果、外部链接失效流程。
- 每条主流程都有入口、步骤、结束状态。
- MVP 和后续版本的边界表达清楚。
- 页面规格文档可以直接引用流程编号。
