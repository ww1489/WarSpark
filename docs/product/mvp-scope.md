# WarSpark MVP 范围说明

## 1. 文档目的

本文档用于锁定 WarSpark 首版 MVP 的功能边界、验收标准和明确不做事项。后续讨论任何新功能时，先对照本文档判断是否进入 MVP，避免产品范围持续扩张。

MVP 的目标不是完整复刻 Base Drop、BurntBase 或 War Report，而是验证 WarSpark 的核心价值：

- 用户上传阵型截图后，能看到可理解的识别结果。
- 用户能获得相关攻击视频和防守回放作为学习参考。
- 用户能打开 YouTube 时间戳或复制阵型链接。
- 找阵过程中沉淀的阵型图片和链接能进入轻量阵型库。
- 战争数据首轮直接接入 Clash of Clans 官方 API，并可作为找阵目标上下文。
- 内部 admin API 和后端管理页面能支撑内容维护、审核和失效处理。

## 2. MVP 总目标

WarSpark MVP 聚焦“战争情报 + 找阵核心 + 轻量阵型库 + 内部管理后台”。

首版要证明三件事：

1. 用户愿意上传阵型截图来寻找相似阵型和相关视频。
2. 相关攻击视频、防守回放、阵型链接对用户有实际参考价值。
3. 找阵结果可以沉淀为可浏览、可筛选、可复用的阵型库资产。
4. 当前战争和 CWL 基础数据能把找阵从单点工具变成战前情报流程。

MVP 不追求：

- 精确 AI 阵型识别。
- 自动识别配兵、流派或完整打法。
- 完整 War Report 式多端战争管理工具。
- 面向用户的投稿和社区运营后台。
- 移动 App 或多端同步。

## 3. MVP 功能范围

### 3.1 截图找阵

必须包含：

- 用户可以上传一张 CoC 阵型截图。
- 系统记录上传任务状态。
- 系统展示基础识别信息：TH、截图质量提示、识别状态。
- 系统展示相似阵型候选。
- 系统展示匹配可信度或匹配等级。
- 系统支持低可信度提示。
- 系统支持无结果状态。

自动化优先：

- TH 识别优先由规则、图像特征或模型自动处理。
- 相似度优先使用自动候选匹配结果表达，不承诺 100% 精确算法。
- 上传图片自动完成格式校验、尺寸检查、EXIF 清理、质量判断和压缩归一。
- 低置信度、冲突、疑似重复和异常样本进入后台复核队列。
- 建筑检测数量可以作为可选字段，不阻塞 MVP。
- 截图裁剪、去 UI 遮挡、图像增强可以先不做复杂交互。

不做：

- 不承诺 100% 找到同款阵型。
- 不做大规模视频帧索引。
- 不做游戏客户端自动化截图。
- 不做用户登录后的历史上传记录。
- 不要求人工参与每一次找阵任务。

验收标准：

- 上传入口可见且操作路径清晰。
- 上传后必须进入明确的处理中、成功、失败或无结果状态。
- 成功结果必须至少展示一个相似阵型区域。
- 低可信度结果不能伪装成精确匹配。
- 无结果时必须给出下一步动作：重新上传、查看同 TH 热门视频或手动提交。

上传限制：

- MVP 前台允许匿名上传。
- 只允许 `jpg`、`jpeg`、`png`、`webp` 图片。
- 单图最大 `10MB`。
- 图片最小边长 `512px`。
- 服务端处理时最大边长归一到 `4096px` 以内。
- 上传时去除 EXIF 元数据。
- 按 IP 做基础限流：每分钟最多 5 次，每小时最多 50 次。
- 原始上传图默认保留 7 天；沉淀为阵型库资产的图片必须经过自动质量门槛或后台审核。

### 3.2 相关攻击视频

必须包含：

- 找阵结果页展示相关攻击视频分组。
- 视频卡片展示标题、频道、TH、星数、摧毁率、时间戳。
- 视频卡片支持打开 YouTube 对应时间戳。
- 视频与阵型之间展示匹配关系或关联说明。

自动化优先：

- 视频链接可访问性和时间戳格式优先自动检查。
- 高价值视频时间戳可通过后台维护和修正。
- 视频标签可以只用少量基础标签，如空军、地面、混合、未知。
- 不要求每条视频都有完整流派标签。
- 不要求每条视频都能证明同款阵型，只要清楚标识为相关或相似。

不做：

- 不下载 YouTube 视频。
- 不自动解析视频画面。
- 不自动提取配兵链接。
- 不自动总结打法步骤。
- 不根据用户账号推荐具体打法。

验收标准：

- 用户能从找阵结果页打开至少一个相关视频。
- 视频时间戳跳转清晰。
- 视频卡片必须区分“精确关联”“相似参考”或“同 TH 参考”。
- 如果没有相关视频，必须展示空状态和替代入口。

### 3.3 防守回放

必须包含：

- 找阵结果页展示防守回放分组。
- 防守回放卡片展示视频标题、频道、TH、攻击结果、时间戳。
- 防守回放与阵型或相似阵型建立关联。

自动化优先：

- 首版防守回放可以先通过已有视频时间戳和后台维护样本支撑。
- 视频可访问性、分组字段和基础结果字段优先自动校验。
- 攻击结果字段可以先记录星数和摧毁率。
- 不要求自动判断防守强度。

不做：

- 不做复杂防守评分模型。
- 不做自动提取失败原因。
- 不做跨版本防守强度归因。

验收标准：

- 进攻视频和防守回放必须在视觉和文案上分组清楚。
- 防守回放卡片能说明该阵或相似阵被打出的结果。
- 没有防守回放时，不影响进攻视频和相似阵型展示。

### 3.4 阵型链接

必须包含：

- 阵型详情或找阵结果中展示阵型链接。
- 支持复制或打开官方游戏打开链接。
- 链接记录来源和状态。

链接类型：

- `official_open_layout`：`link.clashofclans.com` 等官方游戏打开链接，用户侧展示为“打开阵型”或“复制阵型链接”。
- `source_page`：公开阵型站、视频说明或整理页面，只作为来源页面展示。
- `backup`：备用阵型链接或备用来源。

自动化优先：

- 官方游戏打开链接格式自动校验。
- 链接可访问性自动检查。
- 失效、跳转异常和来源冲突进入后台处理。

不做：

- 不保证每个阵型都有可复制链接。
- 不承诺自动修复所有失效链接。
- 不绕过第三方站点限制获取链接。

验收标准：

- 有链接时，用户能清楚看到并执行打开或复制。
- 无链接时，页面必须明确显示“暂无复制链接”。
- 链接失效时，必须有失效状态而不是继续展示为可用。

### 3.5 轻量阵型库

必须包含：

- 找阵结果可生成或关联基础阵型记录。
- 阵型记录包含阵型图片、TH、类型、风格、阵型链接、来源、质量状态。
- 提供轻量阵型库列表页。
- 提供阵型详情页。
- 阵型列表支持基础筛选：TH、类型、风格、来源、审核状态。

可以简化：

- 阵型库首版只做浏览、筛选、详情和复制链接。
- 阵型创建、链接检查、质量初筛和重复提示优先自动化。
- 内部管理后台用于修正低置信度、冲突、失效和异常内容。
- 不要求用户投稿、收藏、点赞、评论。
- 不要求复杂排序算法。

不做：

- 不做用户侧投稿审核流程。
- 不做付费阵型或会员阵型。
- 不做 SEO 内容运营系统。

验收标准：

- 用户能从找阵结果进入阵型详情。
- 用户能从阵型库列表筛选并打开阵型详情。
- 阵型详情必须展示图片、TH、类型、来源、质量状态和阵型链接状态。
- 待审核或低置信度阵型必须明确标识。

### 3.6 战争数据

必须包含：

- 用户可以输入部落 tag 或玩家 tag 查询战争情报。
- 系统通过 Clash of Clans 官方 API 接入部落、玩家、当前战争和 CWL 基础结构。
- 展示当前战争状态、双方星数、摧毁率、TH 分布、成员列表、攻击次数和被打情况。
- 页面支持从敌方目标进入找阵流程。
- 找阵结果支持绑定或展示敌方目标的基础上下文。

可以简化：

- 首轮聚焦官方 API 可提供的数据，不伪造官方 API 无法提供的历史数据。
- CWL 可先做到基础轮次和成员结构，不做复杂长期统计。
- 官方 API 不可用时，找阵流程必须仍可独立完成。

不做：

- 不做完整 War Report 式战争看板。
- 不做多账号同步。
- 不做推送提醒。
- 不做小组件。
- 不做完整历史战争分析。

验收标准：

- 能通过官方 API 查询部落、玩家、当前战争和 CWL 基础结构。
- 战争情报页展示数据获取时间和错误状态。
- 用户能从敌方目标进入找阵。
- 找阵结果页能容纳目标序号、玩家名、TH、当前被打情况等字段。
- 即使没有战争数据，找阵流程也能独立完成。

### 3.7 内部管理后台

必须包含：

- 内部 admin API。
- 后端管理页面。
- 阵型管理：查看、创建、编辑、隐藏、审核、质量状态。
- 图片管理：主图、上传图、候选图、参考图、图片质量和可用状态。
- 链接管理：`official_open_layout`、`source_page`、`backup`、链接状态和检查时间。
- 视频时间戳管理：进攻视频、防守回放、关联精度、星数和摧毁率。
- 找阵任务管理：查看任务状态、低置信度结果、失败原因、异常样本。
- 导入任务管理：公开来源、授权导入、导入批次、错误行和处理状态。

不做：

- 不做用户侧投稿审核入口。
- 不做公开社区运营系统。
- 不做付费内容管理。
- 不做多角色复杂权限模型，首版只需要内部管理员能力。

验收标准：

- 内部人员能通过后台修正阵型、图片、链接、视频时间戳和审核状态。
- 后台写操作需要鉴权，不允许匿名访问。
- 后台能处理自动化流程产出的低置信度、冲突、失效和异常内容。

## 4. MVP 页面范围

MVP 必须包含以下页面：

| 页面 | MVP 要求 |
| --- | --- |
| 作战台 / 首页 | 提供上传截图入口和部落 tag / 玩家 tag 查询入口。 |
| 找阵页 | 上传截图，展示上传要求和处理状态。 |
| 找阵结果页 | 展示识别信息、相似阵型、进攻视频、防守回放、阵型链接、低可信度和无结果状态。 |
| 阵型库列表页 | 展示阵型卡片，支持基础筛选。 |
| 阵型详情页 | 展示阵型图片、阵型链接、来源、质量状态、关联视频、防守记录。 |
| 战争情报页 | 接入官方 API，展示当前战争、CWL 基础结构和目标入口。 |
| 后端管理页面 | 管理阵型、图片、链接、视频、审核状态、导入任务和异常样本。 |

MVP 暂不要求完整实现：

| 页面 | 处理方式 |
| --- | --- |
| 复盘页 | 预留数据结构和入口，完整功能进入 V2。 |
| 视频库列表页 | 可作为内部支撑数据，用户侧列表不进 MVP。 |

## 5. MVP 数据范围

MVP 需要支持的核心数据：

- 阵型：图片、TH、类型、风格、来源、审核状态、质量状态。
- 阵型链接：`official_open_layout`、`source_page`、`backup`、链接状态、来源。
- 视频：YouTube ID、标题、频道、时间戳、TH、星数、摧毁率、标签。
- 阵型和视频关联：关联类型、可信度、说明。
- 找阵任务：上传文件、处理状态、识别结果、候选结果。
- 战争数据：部落、玩家、当前战争、CWL 基础结构、成员、目标上下文。
- 后台管理：审核状态、导入批次、链接检查、异常任务。

MVP 不需要支持的数据：

- 用户账号。
- 收藏、点赞、评论。
- 支付、订单、会员。
- 长期历史战争记录。
- 复杂 AI 特征向量索引。
- 自动配兵识别结果。

## 6. 明确不做事项

以下能力不进入 MVP：

- 登录、注册、个人中心。
- 收藏、订阅、付费、会员。
- 用户侧投稿审核后台。
- 移动 App。
- 完整 War Report 式多端工具。
- 完整 BurntBase 式大规模视频帧索引。
- 自动识别流派、配兵链接、打法推荐。
- AI 总结打法步骤。
- 私有 Discord / Telegram 抓取。
- 登录绕过、付费内容绕过。
- YouTube 视频下载。
- 游戏客户端自动化或逆向。
- 公开 SEO 内容运营后台。

## 7. MVP 成功指标

核心指标：

- 上传截图到结果页的完成率。
- 有结果搜索占比。
- 用户点击 YouTube 时间戳的比例。
- 用户复制或打开阵型链接的比例。
- 战争 tag 查询成功率。
- 从战争目标进入找阵的比例。
- 后台处理低置信度和失效内容的完成率。
- 找阵结果沉淀为阵型记录的比例。
- 阵型详情页打开率。
- 阵型库筛选使用率。
- 低可信度结果的退出率。
- 用户是否愿意再次上传截图。

辅助指标：

- 无结果后的重新上传比例。
- 低置信度结果中的视频点击比例。
- 阵型库列表到详情的点击率。
- 阵型链接失效率。

## 8. MVP 完成判定

当以下条件全部满足时，MVP 可以视为达到首版产品验证要求：

- 用户可以完成一次从上传截图到查看结果的完整流程。
- 用户可以通过官方 API 查询战争数据并从目标进入找阵。
- 找阵结果页能展示识别状态、相似阵型、相关攻击视频、防守回放和阵型链接。
- 找阵结果能进入阵型详情。
- 阵型库列表和阵型详情可以浏览基础阵型资产。
- 内部后台可以管理阵型、图片、链接、视频时间戳、审核状态和异常样本。
- 低可信度、无结果、链接失效、视频缺失都有明确状态。
- 文档、数据模型和页面规格对 MVP 边界表达一致。
