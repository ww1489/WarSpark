# WarSpark MVP 验收清单

## 1. 文档目的

本文档定义 WarSpark MVP 和阶段性交付的验收清单，用于产品、开发和 QA 在每个阶段结束时判断交付物是否达到预期。

本文档只定义验收项，不替代自动化测试用例、接口测试脚本或人工测试记录。

## 2. 使用方式

每个阶段验收时按以下结果标记：

| 结果 | 含义 |
| --- | --- |
| 通过 | 功能或文档满足验收项。 |
| 未通过 | 功能或文档未满足验收项，需要修复。 |
| 不适用 | 当前阶段不包含该能力，且已在范围文档中说明。 |

验收原则：

- 先看 MVP 边界，再看页面和接口。
- 低置信度、无结果、失效链接等异常状态必须被验收。
- 不把未来功能算作当前阶段缺陷。
- 不用“看起来能用”替代明确字段和状态检查。

## 3. Phase 0 文档与范围验收

| 验收项 | 依据 |
| --- | --- |
| 已有总版 PRD，明确 WarSpark 是战争情报站，而不是单纯阵型图库。 | `docs/product/warspark-prd.md` |
| MVP 范围明确包含截图找阵、轻量阵型库、相关视频、防守回放和战争数据预留。 | `docs/product/mvp-scope.md` |
| MVP 范围明确不包含登录、收藏、付费、完整 War Report、移动 App、自动配兵识别和 AI 打法推荐。 | `docs/product/mvp-scope.md` |
| 用户流程覆盖首页找阵、战争目标找阵、结果进入详情、找阵沉淀阵型库、复盘沉淀资料。 | `docs/product/user-flows.md` |
| 页面规格覆盖作战台、找阵页、找阵结果页、阵型库列表、阵型详情、战争情报页。 | `docs/product/page-spec.md` |
| 内容与数据边界明确允许来源和禁止来源。 | `docs/product/content-data-policy.md` |
| 数据模型覆盖阵型、图片、链接、视频、找阵任务、匹配结果和战争快照。 | `docs/architecture/data-model.md` |
| 实施路线图拆分 Phase 0 到 Phase 5，并说明每阶段交付物和风险。 | `docs/project/implementation-roadmap.md` |

## 4. Phase 1 轻量阵型库验收

### 4.1 阵型数据

| 验收项 |
| --- |
| 阵型主记录包含 TH、类型、风格、来源、审核状态、质量状态和可见性。 |
| 阵型至少可以关联一张图片。 |
| 阵型可以没有 OpenLayout，但页面必须显示暂无复制链接。 |
| OpenLayout 支持 `active`、`unverified`、`broken`、`missing` 状态。 |
| 低可信阵型在列表和详情中有明确标记。 |
| 被拒绝或隐藏阵型不进入公开列表。 |

### 4.2 阵型列表页

| 验收项 |
| --- |
| 列表页可以展示阵型图片、TH、类型、风格、来源、质量状态和链接状态。 |
| 列表页支持 TH、类型、风格、来源、审核状态等基础筛选。 |
| 筛选无结果时展示空状态和重置筛选动作。 |
| 图片加载失败时有占位状态，不导致页面崩溃。 |

### 4.3 阵型详情页

| 验收项 |
| --- |
| 详情页展示主图、TH、类型、风格、来源、审核状态和质量状态。 |
| 详情页展示 OpenLayout 或无链接状态。 |
| OpenLayout 失效时禁用打开和复制动作。 |
| 详情页分组展示相关攻击视频和防守回放。 |
| 无视频或无防守回放时有明确空状态。 |

## 5. Phase 2 截图找阵验收

### 5.1 上传入口

| 验收项 |
| --- |
| 用户可以从作战台或找阵页上传一张截图。 |
| 上传接口拒绝不支持的文件格式。 |
| 上传接口拒绝超过大小限制的文件。 |
| 上传成功后创建找阵任务并返回任务 ID。 |
| 用户上传图片保存为任务输入，不默认成为公开阵型主图。 |

### 5.2 任务状态

| 验收项 |
| --- |
| 任务支持 `created`、`processing`、`matched`、`low_confidence`、`no_result`、`failed` 状态。 |
| 任务处理中时前端展示处理中状态。 |
| 任务失败时前端展示失败原因和重新上传入口。 |
| 任务无结果时前端展示无结果状态和替代入口。 |
| 低置信度结果必须有页面顶部提示。 |

### 5.3 结果页

| 验收项 |
| --- |
| 结果页展示检测 TH、截图质量和识别状态。 |
| 结果页展示候选阵型和匹配等级。 |
| 结果页明确区分进攻视频和防守回放。 |
| 结果页展示 OpenLayout 链接状态。 |
| 结果页可以在没有战争上下文时独立工作。 |
| 结果页可以从战争目标上下文展示敌方序号、玩家名和 TH。 |

## 6. Phase 3 视频关联验收

### 6.1 视频数据

| 验收项 |
| --- |
| 同一个 YouTube 视频只保存一条主记录。 |
| 不同时间戳通过阵型视频关联记录表达。 |
| 视频关联包含 `attack_video` 或 `defense_replay` 分组。 |
| 视频关联包含 `exact`、`similar` 或 `same_th` 精度。 |
| 视频卡片展示标题、频道、时间戳、星数和摧毁率。 |

### 6.2 视频展示

| 验收项 |
| --- |
| 进攻视频按精确关联、星数、摧毁率和可信度排序。 |
| 防守回放按精确关联、低星、低摧毁率和可信度排序。 |
| 相似参考和同 TH 参考不能展示成精确关联。 |
| 视频失效时禁用打开动作或展示失效状态。 |
| 无进攻视频和无防守回放分别展示空状态。 |

### 6.3 边界

| 验收项 |
| --- |
| 系统不下载 YouTube 视频。 |
| 系统不自动识别配兵链接。 |
| 系统不自动生成打法步骤。 |
| 系统不把相关视频描述为推荐打法。 |

## 7. Phase 4 战争数据验收

### 7.1 战争数据入口

| 验收项 |
| --- |
| 作战台提供部落 tag 或玩家 tag 输入入口。 |
| Tag 格式错误时展示明确错误状态。 |
| 官方 API 未配置时展示战争数据暂不可用。 |
| 官方 API 请求失败时不影响截图找阵入口。 |

### 7.2 战争情报页

| 验收项 |
| --- |
| 战争情报页展示战争状态、双方星数、摧毁率和获取时间。 |
| 战争情报页展示双方成员列表和 TH。 |
| 敌方成员可作为找阵目标进入截图上传流程。 |
| 页面明确展示数据获取时间，避免用户误认为实时数据。 |
| 无当前战争时展示无战争状态。 |

### 7.3 目标绑定

| 验收项 |
| --- |
| 找阵任务可以绑定敌方序号、玩家名、TH 和战争快照。 |
| 绑定目标后，找阵结果页展示目标上下文。 |
| 战争 API 不可用时，已有目标上下文不影响找阵任务读取。 |

## 8. Phase 5 复盘与资料沉淀验收

| 验收项 |
| --- |
| 战后快照可以保留用于复盘。 |
| 攻击记录和防守结果可以关联到阵型或视频。 |
| 复盘中发现的阵型可以进入审核或入库流程。 |
| 复盘中发现的视频时间戳可以进入视频关联流程。 |
| 复盘资料沉淀不要求 MVP 提供完整复盘页面。 |

## 9. API 验收

| 验收项 |
| --- |
| API 统一使用 `code`、`message`、`data` 响应结构。 |
| 截图上传接口返回任务 ID 和初始状态。 |
| 任务状态接口能返回识别 TH、截图质量、错误信息和目标上下文。 |
| 结果接口能返回阵型、进攻视频、防守回放和复制链接状态。 |
| 阵型列表接口支持页面规格中的筛选条件。 |
| 阵型详情接口返回图片、链接、视频、来源和质量状态。 |
| 战争数据接口与找阵接口解耦。 |
| 运营预留接口不暴露为无需鉴权的公开写接口。 |

## 10. 数据与内容边界验收

| 验收项 |
| --- |
| 所有外部图片、链接和视频时间戳都有来源记录。 |
| 公开页面整理的内容保留来源 URL。 |
| 授权导入内容保留导入来源或批次。 |
| 私有 Discord 或 Telegram 不作为默认抓取来源。 |
| 不绕过登录、付费或第三方访问限制。 |
| OpenLayout 和 YouTube 只保存引用和状态。 |
| 用户上传截图不自动公开展示。 |

## 11. 失败场景验收

| 场景 | 预期结果 |
| --- | --- |
| 图片格式不支持 | 上传失败，提示重新选择。 |
| 图片过大 | 上传失败，提示更换或压缩。 |
| 图片无法读取 | 不创建或失败任务，显示错误。 |
| 找阵处理失败 | 任务进入 `failed`，可重新上传。 |
| 找阵无结果 | 展示无结果状态和替代入口。 |
| 只有低可信结果 | 展示候选和低置信度提示。 |
| OpenLayout 失效 | 禁用打开和复制。 |
| 视频不可访问 | 展示失效状态。 |
| 官方 API 不可用 | 战争数据不可用，找阵流程仍可使用。 |
| 阵型被隐藏或拒绝 | 不进入公开列表。 |

## 12. 发布前总验收

发布 MVP 前需要满足：

- 核心文档已完成并保持一致。
- 用户可以完成从上传截图到查看结果的闭环。
- 找阵结果页展示识别信息、候选阵型、进攻视频、防守回放和 OpenLayout 状态。
- 阵型库列表和阵型详情可以浏览基础资产。
- 低置信度、无结果、失败、失效链接和无视频状态均有前端表现。
- 外部内容来源和禁止行为符合内容边界文档。
- Swagger 或接口文档与实际实现一致。
